# Stage 63: skinned characters

Plan: [README.md](README.md), 2.6 (animation in steps, the gate "no smear of the pose before"), 2.15 ("Animation": the core of keys and tracks, then skinned characters, then the timeline), 3.2 item 9. Report: `docs/part6/stage-63.md`. Needs: stage 62 (the clip, the animator, `PoseJumps`, the jump frame of the TAA). Stage 64 (the timeline) builds on it.

Goal: a glTF file with a skin loads as a character: its joints, its weights, and its animations as clips. An object with the model and the component `animator` plays a clip of the file (`models/figure.glb#wave`): the joints move, the GPU bends the mesh in each frame that the pose changes, rays see the bent mesh, and a moving limb has the motion of its own vertices, so the denoiser and the TAA keep its history. A `STEP` sampler of glTF is a step track: the pose jumps with no blend and with no smear.
Gate: a test in code: a generated glTF with three joints and two animations loads with its joints, inverse bind matrices, and weights; its `STEP` animation is a step track on the joint by name, `LINEAR` a linear one; an animator with the step clip snaps the joint pose at the key (`previous == current`, one more `PoseJumps`); the CPU skin of a vertex of a joint turned 90° is at the place of the reference. The picture: in the scenario `skin_jump_720p` (the figure snaps its arm by a step key at 1 s, camera and light at rest), the crop of the place that the arm left, 4 frames after the jump, has no larger error against the reference than the crop of the cube in `jump_720p` 4 frames after its jump (`bench.py quality --crop`): a skinned jump smears no more than a rigid one. The lighting part of 2.6 (the old shadow fades over about 8 frames) stays deferred to the quality session (`HANDOVER.md`). The game plays as before: the trip run, `bench.py gate`, the GPU time against `s62`.

## Now (the code at stage 62)

- The glTF loader (`crates/assets/src/model.rs:291`, `read_gltf`) walks the node tree from the scene roots and flattens it: each primitive gets the transform of its node baked into its vertices (`:330`, `read_primitive` `:367`). It reads meshes, materials, textures, and point lights. No skin, no `JOINTS_0` or `WEIGHTS_0`, no animation, no node names. `Mesh` (`crates/assets/src/mesh.rs:115`) has positions, normals, indices, texture coordinates, a material. `Model` is a list of mesh handles and lights. The `gltf` crate (workspace, default features) reads skins and animations: no new dependency.
- The clip (`crates/assets/src/clip.rs`): `Track { channel, mode, keys }` (`:82`) has no `target`; a rotation key is degrees around X, Y, Z. `KeyMode` is `Step | Linear`. `DataAssets` reads a clip from a `<name>.clip.ron` file only.
- The animator (`crates/scene/src/animation.rs`): `animate` (`FixedUpdate`, exclusive) writes `Interpolated::current` of the object of the animator, relative to its rest pose (`:187`); a step write is `Interpolated::jump`, counted in `PoseJumps` (`write_pose`, `:202`).
- A model in a room: a prop with `mesh: File(..)` gives no object entity (`crates/scene/src/room.rs:1721`): `spawn_loaded_models` (`:1945`) spawns one entity for each mesh, with the transform of the load, so no object component (an animator) can be on a model. The player has its own path (`crates/gameplay/src/player.rs:339`, `give_mesh`): one entity with the first mesh of the model, which draws the whole group. The player prefab is a capsule (`game/assets/rooms/prefabs/player.prefab`). A walker faces +Z (`player.rs:765`).
- The meshes on the GPU (`crates/render/src/meshes.rs`): all meshes of a model are one group: one BLAS, one block of the mesh table, normals per triangle corner (`NormalBuffer`, `shaders/scene.glsl:27`). A table entry is 64 bytes and full (`MeshEntry`, `scene.glsl:62`).
- The acceleration structures (`crates/gpu/src/accel.rs`): a BLAS is built one time (`create_blas`, `:130`; `PREFER_FAST_TRACE`, mode `BUILD`, `:81`); its vertex buffer goes away after the build (`:278`). The TLAS is built in full (`PREFER_FAST_BUILD`, `:115`) in a frame whose instance list differs from the last build (`BuildTlas`, `crates/render/src/passes.rs:250`): that is how `bodies_720p` moves 50 cubes. No refit anywhere. Each buffer has storage, device address, and build input usage (`crates/gpu/src/lib.rs:284`): a compute shader can write a buffer that a BLAS then builds from, with no new Vulkan feature.
- Motion vectors: `extract_instances` (`meshes.rs:550`) gives each instance the transform of the frame before; `BuildTlas` writes it to the instance buffer (`passes.rs:231`, 48 bytes, `motion.rs:28`); `previous_world` (`shaders/trace.glsl:356`) moves the hit point in the space of the instance by it. Right for a rigid object only: a bent vertex has no motion of its own.
- Rule 2 and 3 hold: `maki_gpu` has the only `ash` types; the passes read `ExtractedInstances` and `GpuMeshes` of the render world.

## The way

- **The skin in the model asset.** `Model.skeleton: Option<Skeleton>`: `joints: Vec<Joint { name, parent: Option<usize>, rest: Transform }>` in parent-first order, `inverse_binds: Vec<Mat4>`. A joint is named by its glTF node name (`joint<index>` for a node with no name): it is a part of a model file, not a room object, so ADR 0001 does not apply. A skinned primitive keeps its vertices in bind space (glTF ignores the node transform of a skinned mesh) and gets `Mesh::with_skin(joints: Vec<[u32; 4]>, weights: Vec<[f32; 4]>)`: at most 4 for each vertex, the weights normalized, each index checked in `Mesh::new`. One skin for each file (a second skin: a warning, left out). The pure function `maki_assets::skin::skin_vertex(position, normal, joints, weights, palette)` is the reference of the shader and of a later software tracer.
- **Clips from the file.** `Track.target: Option<String>` (`#[serde(default)]`, not written when none): a joint of the model of the object; none is the object, as in stage 62. `maki_assets::clip::gltf_clips(path)` makes a clip for each glTF animation: `STEP` is `KeyMode::Step`, `LINEAR` is `Linear`, `CUBICSPLINE` is `Linear` on its values with a warning; the values are relative to the rest of the joint (rest⁻¹ x value), rotations in degrees as the clip of stage 62. A `DataRef<Clip>` names one as `<model file>#<animation name>`; `DataAssets` reads the clips of the file and forgets them on a change of the file, as a clip file.
- **The pose of the joints** (`maki_scene::skin`): the component `SkinPose { previous, current }` (local joint transforms, as `Interpolated` for an object) on the object of a skinned model, and `SkinPalette(Vec<Mat4>)` (model-space joint x inverse bind), made in `Update` from the blend and written only when it differs. `animate` writes a track with a target into `SkinPose::current`, relative to the joint rest; a step write sets both and counts one `PoseJumps` when the pose changes. `ResetPlay` gives back the rest. A model with a skeleton keeps its object entity: `spawn_loaded_models` gives it the first mesh (the group draws the whole model, as the player model) and `SkinPose`, so object components (the animator) are on it. A model with no skeleton spawns as now.
- **GPU skinning** (`crates/render/src/skins.rs`, `shaders/skin.comp`): `extract_skins` copies each changed `SkinPalette` with the id of its instance into `ExtractedSkins` (rule 3). For each skinned instance: its own block of the mesh table (the entries of its group with its own normal address), a palette buffer for each frame slot, two corner position buffers (this frame and the frame before, swapped), a corner normal buffer, and its own BLAS. The pass `skin` (before `build_tlas`) runs `skin.comp`, one thread per triangle corner, only for an instance whose palette changed. The BLAS is built from the corner positions with no index list (three corners for each triangle, the order of the normals).
- **The BLAS: built again, not refitted.** `maki_gpu` gets `create_dynamic_blas` (the vertices in a buffer of the caller; the storage and the scratch kept) and `rebuild_blas` (recorded in the frame: a barrier from the compute write to the build input read, then a `BUILD` into the same structure). A rebuild only in a frame where the palette changed; then the TLAS is built too, also with an equal instance list (Vulkan: a TLAS that names a changed BLAS is built again). Why not a refit (`ALLOW_UPDATE`, mode `UPDATE`): a step clip moves a limb far in one frame, where a refit gives the worst trees; a character of some thousand triangles builds in tens of microseconds; one path. A refit is a choice of the optimization session (`HANDOVER.md`).
- **Motion vectors of a bent vertex.** The instance buffer gets one more value: the bindless index of the corner positions of the frame before (64 bytes for each instance; none for a rigid instance). `previous_world` reads the three previous corners of the hit triangle, blends them by the barycentrics, and moves the point by the previous transform. In a frame with no new pose the index is that of the current positions: zero motion of the skin. A step pose is a counted jump, so the jump frame of the TAA of stage 62 drops the pixels that the limb left.
- **The test character, generated by code.** `tools/gen_models.py` writes `models/figure.glb` (boxes: a body and two arms; joints `root`, `arm_l`, `arm_r`; a vertex near a shoulder on two joints) with two animations: `wave` (`LINEAR`, an arm turns up and down in 1 s) and `hop` (`STEP`, both arms snap up at 1 s and back at 2 s). Its front faces +Z, as a walker. `write_glb` of `tools/gen_textured.py` learns skins and animations. No Blender: the converter needs a Blender install, CI has none. The unit tests write their small skinned glTF in Rust (as `write_gltf` in `model.rs`).
- **The player** stays a capsule. A player prefab with a skinned model file draws it in its bind pose (no `SkinPose` on the player path); a skinned player is a later step of the owner's content.

## What to watch for

1. **The pictures**: the instance buffer grows from 48 to 64 bytes and `previous_world` gets a branch for all hits: the pictures of the benchmark rooms must stay equal (`bench.py gate`); a GPU-time step goes into the report (no optimization in the stage).
2. **The barriers**: compute write of the corners, then the BLAS build, then the TLAS build, then the trace; the frame before still reads the positions of the frame before (the swap, by frame slot). Validation with synchronization on.
3. **Normals**: the skin bends the normals with the palette (no non-uniform scale in a joint: a warning at load); the normals stay per corner, as `NormalBuffer`.
4. **Determinism**: joint poses from fixed-step time; the blend in `Update`; a palette written only when it differs, so a pose at rest makes no skin pass and no rebuild.
5. **Rule 3**: the passes read `ExtractedSkins`, never `SkinPose`. **Rule 2**: `create_dynamic_blas` and `rebuild_blas` take handles, no `ash` type.
6. **The mesh table**: each skinned instance takes the entries of its group (`MAX_MESHES` 1024): many copies of a character fill it; an error once, as the instance limit.
7. **Collision**: the collider of a skinned model is the box of its bind pose. Not in this stage.
8. **Not in this stage**: a skinned player (content of the owner), blends between clips, root motion, morph targets, more than 4 weights, a refit, a joint as a parent of another object (a held item), the timeline (stage 64), the lighting part of the 2.6 gate (the quality session).
