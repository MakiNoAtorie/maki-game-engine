# Stage 64: the timeline, and light animation

Plan: [README.md](README.md), 2.6 (the step mode), 2.7 (the template "Cutscene trigger"), 2.13 (the timeline in the bottom dock, the layout "Animate"), 2.15 ("Animation": the timeline after skinned characters; light animation on its tracks; "Animate" comes with the timeline; the slice item 5: the camera moves, a character walks and plays a clip, a light flickers), 3.2 items 6 and 26. Report: `docs/part6/stage-64.md`. Needs: stage 63.

Goal: a timeline is a component of a room object: tracks of keys, each on an object of the room by its id, on the same channels and modes as a clip. An event row or a script plays it, waits for its end, stops it, or skips it to its end. A light has fields that animate by themselves (flicker, pulse, fade, a color by temperature), and a timeline track can key them. The editor has a timeline panel. A cutscene of the slice can be made with no code.
Gate: a test in code: a timeline with a step position track on one object and a linear field track on the intensity of a lamp writes each value at its time and jumps with no blend at a step key; `PlayTimeline(t, wait)` waits until the last key; `StopTimeline(t, end)` writes the end values; a text key on `animator.clip` cuts the clip of a character; a light with `flicker` gives the same intensities in two runs and holds each for `1 / flicker_rate` s; `kelvin_rgb(6500)` is white within 3 %. The game plays as before: the trip run, `bench.py gate` (equal: no benchmark room changes), the GPU time against `s63`.

State: written by the session from the plan and the code at commit `67f4bd3`; a proposal: taken as given if the owner does not change it.

## Now (the code at stage 63)

- The clip (`crates/assets/src/clip.rs`): `Clip { mode, fps, length, tracks }`, `Track { channel, target, mode, keys }`, `Channel::{Position, Rotation, Scale, Field { component, field }}`, `KeyValue::{Number, Vector, Switch, Text}`; pure `clip_time` and `Track::sample`. A track names the object of the animator only, or a joint by its name (`target`): "a reference to another room object by name would break ADR 0001" (`stage-62.md`, 4).
- The animator (`crates/scene/src/animation.rs`): `animate` (exclusive, `FixedUpdate`, `.before(move_movers)`; `run_events.after(animate)`) runs `play` for each animator: fixed-step time as a count, the cut, the rest pose, one warning for each track that does not write; transform tracks into `Interpolated` (`write_pose`, a counted jump in `PoseJumps`), joint tracks into `SkinPose` (`write_joints`), field tracks through `write_field`. All of it is in the one function `play`, for the entity of the animator.
- A field of another object at run time: `SetField(object, component, field, value)` and `write_field` (top-level fields with a `Live` form; `light` has `radius, color, intensity, on, direction, cone`). `MoveObject` (`crates/events/src/objects.rs`) waits by its handler: it returns false until done, with its state in `Step::memory`. Command rows and scripts name objects by `ObjectId` (`Kind::Object`); a script runs a command with `ScriptContext::call`.
- Lights: `LightSource` (room component `light`, `crates/scene/src/room.rs:691`) gives the `Light` that the renderer reads; a changed `Light` is a soft reset (`crates/render/src/light.rs:108`). No flicker, pulse, fade, or temperature: the template `flickering_light.rs` writes `Light::intensity` from a letter pattern; `light_control.rs` moves the first light (debug). No preset.
- The camera is not a room object: `FollowCamera` follows the player from `[camera]` of the config (`crates/gameplay/src/camera.rs`). `SetPlayState(Cutscene)` and `GiveControl` exist (`crates/gameplay/src/game.rs`).
- The editor: panels are files of `crates/editor` added by `add_tool_panel` (`panels.rs::build`); the layout "Animate" waits for "a later panel (the timeline)" (`panels.rs:42`). The inspector draws a `Fields` type with no panel code; `Document::component_tree` / `set_component_tree` edit a component; `patch_room` shows a light or a prop pose with no reload. No ruler, key, or curve widget.

## The way

- **The timeline** (`maki_scene::timeline`): the object component `timeline` (`#[derive(Fields)]`): `mode`, `fps`, `length`, `looping` (false), `playing` (false: true plays at the room load), `tracks: Vec<TimelineTrack { object: ObjectId, track: Track }>`. Object 0 is the object of the timeline. Its own type, not a `Clip`: a clip is a file for any object and names none; a timeline belongs to one room, so ids are right (ADR 0001). The `Track` and its sampling are those of the clip, with no copy. Run state in the required `TimelinePlayback` (steps, the rest pose of each target, warnings), as `Playback`.
- **The play**: in `animate`, after the animators (a hook, no new exclusive system): `clip_time`, then for each target the track write of the animator (the prefactor: `play` gives the write of a list of tracks to one entity as `write_tracks`). Transform tracks are relative to the pose of the target at the start of the timeline; a step write is a counted jump. A track on the same channel as an animator wins (it writes last). A child object does not follow (as the animator). The end of a timeline that does not loop sets `playing` to false. `ResetPlay` gives back the rest poses. The room check warns of a track on an object that is not in the room.
- **The commands** (`maki_events`, its own module): `PlayTimeline(timeline, wait)` starts at time 0 (wait: until `playing` is false); `StopTimeline(timeline, end)` (end: the values of the last keys are written: a skip). They are the "Animate" of 2.15. A clip on one character: a text key on `animator.clip` (stage 62's cut).
- **Light animation**: new fields of `light`, each a number so that a timeline track keys it, not written at 0: `temperature` (Kelvin; not 0: the color is `kelvin_rgb(temperature) * color`), `flicker` (0 to 1) and `flicker_rate` (changes in a second, default 10: a step pattern, a seeded hash of the object id and the step: no random state), `pulse` (0 to 1) and `pulse_seconds`, `fade` (seconds for a change of `on`). `kelvin_rgb` is a pure function (linear RGB, the largest channel 1). A light with one of them gets the component `LightAnimation` (the values of the file, the time); a system writes `Light` from it with `set_if_neq`, `.before(animate)`, in fixed-step time. The `Live` form of an animated light reads and writes the values of the file, not the animated `Light`. A light with none gets no new component.
- **Light presets**: prefabs of a light object (stage 49: an instance changes some values). No new code; three test prefabs.
- **The camera object**: the component `camera` (`fov`, `active`): while an object with an active camera is in the room, `FollowCamera` takes its pose (its forward is the target) in place of the follow. A timeline moves it by a pose track and switches it by a switch track.
- **The timeline panel** (`crates/editor/src/timeline_panel.rs`, a tab of the bottom dock, open in "Animate"): the timeline of the selected object, or a pick of the timelines of the room. A row for each track (object name, channel), its keys as marks on a time ruler, a play head that a drag moves (scrub). "Key": a key at the play head with the value of the field of the track's object in the document. A click selects a key; Delete removes it; a drag moves its time. "Add track": an object and a field of its components. Scrub shows the samples in the view through `patch_room` (lights, poses of props with a generated mesh); the document is not changed until a key is. Each change is one step of the history. Pose keys and modes are edited in the inspector of the `timeline`.

## What to watch for

1. **The pictures**: no benchmark room has a timeline, a camera object, or a new light field; no new component on a light with none (`CODING_STANDARDS.md`); never on the first light of a room.
2. **The denoiser**: each change of a light is a soft reset. Flicker steps at its rate; a pulse changes in each fixed step. Measure the noise of `light_anim_720p` (`bench.py quality`) and its GPU time, and report; no optimization (`HANDOVER.md`).
3. **The schedule**: the timeline is a hook of `animate`; the light system needs an order against `animate` only. Bevy refuses an ambiguous order at the start: the app test of each build form.
4. **Determinism**: fixed-step time as a count; the flicker from a hash, not a random state.
5. **The script DLL**: new types, no new `ScriptContext` function (a script calls the commands). The symbol count.
6. **Not in this stage**: event or command keys on a track, curves with tangents, blends, a timeline file shared by rooms, a child that follows its parent, a key of a pose from the gizmo (the inspector edits pose keys), a color picker on the ruler, a skip by the player in the engine (the template "Cutscene trigger" reads an action and runs `StopTimeline(t, end)`), the effect stack on tracks (item 20).
