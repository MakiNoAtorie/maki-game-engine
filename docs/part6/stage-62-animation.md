# Stage 62: the core of animation: keys, tracks, the step mode

Plan: [README.md](README.md), 2.6 (animation in steps), 2.15 ("Animation": one core of keys and tracks first, then skinned characters, then the timeline), 3.2 items 6, 9, 26. Report: `docs/part6/stage-62.md`. Needs: stage 61. Stage 63 (skinned characters) and stage 64 (the timeline, light animation) build on it.

Goal: a clip is a data asset: tracks of keys, each track the pose of an object (position, rotation, scale) or a field of a component of it, each with the mode `Step` or `Linear`, and the clip with an optional frame rate of its own. An object with the component `animator` plays a clip: a step key holds its value until the next key, a clip at 12 frames in a second plays its curves in steps, and a change of the clip is a cut. A pose that jumps does not smear in the picture.
Gate: a test in code: a clip with step keys holds each value until the next key and jumps with no blend between fixed steps; a linear clip at 8 frames in a second changes its value 8 times in a second; a field track changes the intensity of a light; a change of `animator.clip` by `SetField` starts the new clip at its first key, with no blend. The picture: in the scenario `jump_720p` (an object that jumps by a step clip, the camera at rest), the crop of the place that the object left, 4 frames after the jump, has no larger error against the reference than the same crop 4 frames after a light change (`bench.py quality --crop`). The game plays as before: the trip run, `bench.py gate`, the GPU time against `s61`.

State: written by the session from the plan and the code at commit `2d394e8`; a proposal: taken as given if the owner does not change it.

## Now (the code at stage 61)

- `maki_core::Interpolated { previous, current }` (`crates/core/src/interpolation.rs`): `FixedUpdate` writes `current`; `shift_poses` (`FixedFirst`) copies it to `previous`; `interpolate_transforms` (`Update`) writes the blend into `Transform`. A new `current` thus slides over one fixed step; `snap` sets both and the picture jumps. The room load gives `Interpolated` to the object entity of an object with an object component (`crates/scene/src/room.rs:1622`); a prop with no such component has a `Transform` only. Poses are in the space of the room, also for a child object; there is no transform hierarchy.
- Fields (`crates/core/src/fields.rs`): `#[derive(Fields)]` gives the table (`Kind`: Number, Switch, Text, Vector, Color, ...) and the value as a `serde_json::Value` tree; `FieldTypes` finds a table by name. A data asset (stage 57, `crates/assets/src/data.rs`) is a file `<name>.<type>.ron` of a type with `DataAsset`; `DataRef<T>` names one; `DataAssets` reads it at first use and forgets it on a change of the file. The inspector edits it with no panel code.
- `SetField(object, component, field, value)` (`crates/events/src/builtin.rs:240`, `set_field`): through `Live { get, set }` of `ComponentTypes` (`crates/scene/src/object.rs:229`), a top-level field of the tree, written only if the value differs. `add_object_component` gives a component of `bevy_ecs` a live form that inserts the whole component again.
- `MoveObject` (`crates/events/src/objects.rs:146`): a line from the place to a target in some seconds; it writes `Interpolated::current` of the object and its children (`tree_entities`, by the parent chain of the room), and the offsets in `MovedObjects`.
- The glTF loader (`crates/assets/src/model.rs`) reads meshes, materials, textures, point lights, and flattens the node tree into model space (`:320`). It reads no animation, sampler of a channel, or skin.
- The renderer: `extract_instances` (`crates/render/src/meshes.rs:547`) gives each instance its transform of the last frame (`:578`); the trace writes the screen motion of each pixel from the two. A changed instance is a soft reset (`soften_accumulation`, `:566`): a short history of the indirect light. The denoiser keeps the history of a pixel only on the same surface (normal and distance, `crates/render/shaders/denoise_temporal.comp:136`). The TAA tests the surface only for a pixel that moves (`crates/render/shaders/taa.comp:228`); at rest only the 3x3 color range and `new_light` (from the denoiser) guard it.
- So an object that jumps today: its own pixels find their history by the motion (correct for a rigid object); the pixels that it left are at rest, so the TAA keeps the old pose where the 3x3 range is wide (an edge, a dark object on a dark floor). No test or scenario measures it.

## The way

- **The clip** (`maki_assets::clip`, so the glTF loader of stage 63 makes clips too): `Clip { mode, fps, length, tracks }`, a data asset `clip` (`<name>.clip.ron`, in the inspector with no panel code). `Track { channel, mode, keys }` on the object of the animator only: a reference to another room object by name would break ADR 0001 (ids); stage 63 adds a `target` (a joint of the model, by its name in the model file) as a field with a default, so a clip file of this stage still reads. `channel` is `Position | Rotation | Scale | Field { component, field }` (a top-level field, as `SetField`). A key is `{ time, value }`, the value a `KeyValue` (`Number | Vector | Switch | Text`); a rotation key is degrees around X, Y, Z, as `PoseDef`. `mode: Step | Linear` on the clip, `Option` on a track (none: that of the clip). `fps: Option<f32>`; `length`: 0 is the time of the last key.
- **Sampling is a pure function**: `clip_time(time, length, looping, fps)` (the loop, the hold at the end, the cut to the frame rate: `floor(t * fps) / fps`, with a small epsilon so that 1/12 s of fixed steps lands on its frame) and `Track::sample(t)`: `Step` holds the key at or before `t`; `Linear` lerps numbers and vectors and slerps rotations (the short way); a switch or a text is always a step. Tests of each case, with no app.
- **Transform tracks are relative** to the rest pose of the object (its pose of the file at the start of the clip): pose = rest x key. A clip then plays on any copy of an object. Stage 63 converts the absolute glTF values of a joint at import (rest⁻¹ x value); slerp keeps its form under that product.
- **The animator** (`maki_scene::animation`, `AnimationModule`): the object component `animator` (`#[derive(Fields)]`: `clip: DataRef<Clip>`, `speed` 1.0, `looping` true, `playing` true), with the live form of `add_object_component`. Its run state is the required component `Playback` (not in the file: the time, the clip that plays, the rest poses of the targets), because the live form inserts the whole `animator` again and so drops what is not in its fields. A clip other than the one that plays (a `SetField` of `clip`) is a cut: time 0, no blend. `ResetPlay` takes the targets back to their rest poses and the time to 0.
- **The write**: one system `animate` in `FixedUpdate`, with fixed-step time (never frame time). A transform track writes `Interpolated::current`; a write from a step (a step key, a clip with `fps`, a cut, the loop of a step clip) is a `snap`, so the picture jumps; a linear one blends as now. A target with no `Interpolated` gets one at its first write (only an animated object; none is in a benchmark room). A field track writes through `Live`, only a different value (the core of `set_field` becomes `maki_scene::write_field`, used by both). `animate` is exclusive (`Live::set` has the world): `.before(move_movers)` in the scene module, and `run_events.before(animate)` beside `run_events.before(move_movers)` (`crates/events/src/lib.rs:181`): a `SetField` of this step plays in this step, and the physics (after `move_movers`) sees the new poses.
- **A pose jump for the renderer**: the resource `maki_core::PoseJumps(u64)`, one more on each snap of a pose that changes. An `Extract` system of the renderer sees it changed and calls `RenderWorld::jump_accumulation`: a soft reset, and the TAA tests the surface at rest too in that frame (a push value), so the history of a pixel that the object left is dropped. A camera cut and a room change keep their own paths. Stage 63 snaps a skinned pose with the same resource.
- **The tests of the picture**: the CPU seam in code (a step key snaps, `PoseJumps` grows once per jump, the extract asks a jump, the TAA push value is set in that frame only). The picture: the scenario `jump_720p` of `tools/bench.py`, a generated scene with one object and a step clip of 1 s; `bench.py reference` with the object at its second place, `quality --crop` of the first place, against the same crop after a light change (`--bench-light-frames`).
- **Not the events**: no new event command and no new function of `ScriptContext`. `SetField` on `animator` starts, stops, cuts, and changes the speed. "Animate" comes with the timeline (2.15); a `play` of a script with stage 63.

## What to watch for

1. **The pictures**: a write only of a different value (`set_if_neq`, the compare of `write_field`); `Interpolated` only on targets of a clip; no animator in a scenario room.
2. **The schedule**: `animate` is exclusive; bevy refuses an ambiguous order at the start of the app. An app test of each build form starts the module list.
3. **Determinism**: time from the fixed step; the cut to the frame rate gives the same frame in each run (epsilon), so a test and a benchmark give the same poses.
4. **Light tracks**: each write of a light is a soft reset of the picture. A linear light track at each step keeps the history short; a step track resets only at a key. Measure the noise of the test room.
5. **Collision**: a fixed collider does not follow an animated prop (only a mover's does). Not in this stage; the warning of the room check names it.
6. **The 2.6 gate in stage 63**: a rigid object has exact motion; a skinned pose has none until stage 63 writes the motion of its vertices. The jump frame of the TAA is the seam it uses; stage 63 measures its own `jump_720p` with a character.
7. **Not in this stage**: glTF animations, the `STEP` sampler of glTF, skins (stage 63: the loader reads no animation now); the timeline, its panel, the command "Animate", light presets (stage 64); blends between clips, curves with tangents, events at keys, root motion; another object as a target (the object of the animator only; joints in stage 63).
