# UX pass: bugs found

These bugs were found in the UX pass. The bug pass (branch `chore/ux-bugs`) gave each a status.

1. `crates/engine/src/editor_program.rs:31` — `USAGE` has runs of spaces in the middle of lines (`...]...     [--input-script` and `one on each line; see ...     (default: ...`). The string literal continues across source lines without a `\` line continuation, so the indentation becomes part of the text. `maki-editor --bad` prints a broken usage message.
   - **Already fixed**: the UX pass rewrote USAGE with one option per line.
2. `crates/devtools/src/gameplay_panel.rs:53` (medium) — Walk and run speed sliders are independent, so run speed can be set below walk speed (e.g. walk 8, run 2), making 'run' slower; also range 0..=10 clamps values that a prefab may hold above 10, and a slider drawn from an out-of-range value gets clamped and written back on the first touch. Fix: Clamp run_speed to at least walk_speed and use a range that includes the current value (e.g. 0.0..=max(10, value)).
   - **Fixed**: the slider range includes the current value (max(10, value)); run speed is clamped to at least walk speed.
3. `crates/devtools/src/gameplay_panel.rs:61` (low) — With several PlayerDef entities, only the first one is shown but the edit is written to all of them, overwriting differing values of other players. Fix: Write only to the entity that was read, or show a per-entity section.
   - **Fixed**: the edit is written only to the entity that was read.
4. `crates/devtools/src/log_panel.rs:174` (medium) — `stick_to_bottom(true)` always forces the view to the end, so a user who scrolls up to read an error is yanked down by every new line. Fix: Let stick_to_bottom release when the user scrolls up (egui does this by default only if not forced) or add an 'Auto-scroll' toggle in the toolbar.
   - **Not a bug**: egui `stick_to_bottom(true)` releases when the user scrolls up.
5. `crates/devtools/src/log_panel.rs:175` (medium) — Rows are laid out with fixed height `text_style_height(Body)` but each row is a `ui.horizontal` with item spacing and a link/strong widget, so show_rows virtualization drifts and rows can overlap or scroll position jumps (the spacing is not included). Fix: Use `height + ui.spacing().item_spacing.y` as the row height.
   - **Not a bug**: egui `show_rows` adds `item_spacing.y` to the row height itself.
6. `crates/editor/src/camera.rs:143` (medium) — view_top sets distance = size*0.55/half_fov + height without clamping, but move_camera clamps distance to 200 on the next frame, so for large rooms (e.g. 200 m wide) 'View from the top' no longer shows the whole room. Fix: Clamp the distance in view_top the same way, or raise the upper limit (e.g. to a multiple of the room size).
   - **Fixed**: the orbit distance limit is a `MAX_DISTANCE` of 2000 m, so the top view of a large room is not clamped.

   - **Fixed**: a failed reload stores the new file time, so the error shows once. The fields are not disabled.
