# UX pass: detailed findings of the file reviews

One Sonnet reviewer per file group. Each line: severity, place, problem, proposed fix. The fixers decide; a finding they do not take is listed in `CHANGES.md`.

## config.toml

- **medium** `:1` — The editor takes its window size and vsync from the game's config.toml (1280x720, not maximized), so the editor docks start cramped and a game-resolution change also resizes the editor; the window size is not remembered between sessions. Fix: Give the editor its own window defaults (maximized, saved size and dock layout on exit) instead of reading [window] of the game config.

## crates/devtools/src/gameplay_panel.rs

- **medium** `:14` — Panel edits are runtime-only and lost on exit, but nothing in the panel says so; users who tune values expect them to be saved (the doc comment says it, the UI does not). Fix: Add a weak label at the top 'Changes last until the game stops; not saved' and an optional 'Copy values' button.
- **medium** `:15` — When neither CameraSettings nor a player entity exists the panel renders completely empty, a dead end with no explanation. Fix: Show 'No gameplay settings loaded. Start play mode or add the gameplay modules.' when no section was drawn.
- **medium** `:17` — Sections are `collapsing` with no default_open and no stable id/state, so they start closed and the panel looks empty; collapsed state resets if the section is hidden and shown again. Fix: Use `egui::CollapsingHeader::new("Camera").default_open(true)` so the controls are visible at once.
- **low** `:19` — Slider labels are inconsistent: 'field of view' has no unit, others use 'x, s' / 'x, m' style, and none have a tooltip or a reset-to-default. Fix: Label 'Field of view, deg' consistently and add a per-section 'Reset' button that restores the default settings.
- **low** `:36` — Position and target are three unlabelled DragValues (no x/y/z prefix) with the name placed after them, and no unit, so the axes are ambiguous. Fix: Use `.prefix("x ")`, `"y "`, `"z "` on each DragValue and put the label first, adding ' m' as suffix.

## crates/devtools/src/log_panel.rs

- **high** `:165` — Clear wipes up to 5000 lines instantly with no undo or confirmation, and also clears lines hidden by the current filter. Fix: Add a tooltip 'Clear all log lines (also hidden ones)', and keep the lines until the next frame via an undo, or clear only the filtered view.
- **medium** `:150` — Level toggles show no counts and an all-off filter silently shows an empty panel with no message; the user cannot tell if the log is empty or filtered. Fix: Show counts per level on the toggles (e.g. 'Errors 3') and a centered 'No lines match the filter' label when lines is empty.
- **medium** `:154` — The 'source' field is a bare hint with no tooltip; users do not know it is a prefix match on the module path (e.g. maki_scene), and the search field has an icon but the source field has none. Fix: Add on_hover_text 'Module path prefix, e.g. maki_scene::room' and rename the hint to 'module prefix'.
- **medium** `:195` — Log text is a plain label: it cannot be selected or copied, and multi-line messages are cut to one row, so users cannot paste an error into a bug report. Fix: Use `egui::Label::new(text).selectable(true)` with a right-click 'Copy line' / 'Copy all' menu, and show full text on hover.
- **low** `:160` — The search field has no clear (x) button or Escape handling, and there is no way to reset the filters to default. Fix: Add a small clear button inside the field or clear on Escape, plus a 'Reset filters' action.
- **low** `:178` — Level is shown only by an icon and color; debug and trace look identical to info (same INFO icon, same weak color), and the level is not available to color-blind users as text. Fix: Use distinct icons or a short level text (DBG/TRC) with tooltip for non-error levels.
- **low** `:187` — The file:line link gives no feedback when the open callback fails or the file does not exist (the click is silent). Fix: Show a notice/log line 'Could not open <file>' when the open handler cannot find the file, and disable the link style when the path is missing.
- **low** `:193` — The repeat count '×N' is placed before the message text with no tooltip, so it reads as part of the source; users do not know it means repeated identical lines. Fix: Add hover text 'Repeated N times in a row' and put the count after the text or in a badge at the right.

## crates/editor/src/camera.rs

- **medium** `:90` — There is no 'focus on selection' (F in Unity/Godot) or double-click-in-outliner framing, and the camera only orbits a fixed target, so finding a selected item in a big room needs manual pan and zoom. Fix: Add a VIEW_FOCUS action (key F) that sets target to the selection center and distance from its bounds.
- **low** `:27` — The binding descriptions are inconsistent and vague: 'Nearer'/'Farther' do not say the wheel zooms, 'Turn the view'/'Move the view' do not use the Orbit/Pan terms of other editors, and T/G do not name the commands. Fix: Rename to 'Orbit view (drag)', 'Pan view (drag)', 'Zoom in (wheel)', 'Zoom out (wheel)', 'Top view', 'Game camera view'.
- **low** `:63` — game_view clamps pitch to 0 while orbiting clamps to 0.05, and a game camera below the floor plane is silently flattened, so 'View of the game camera' can differ from the real game view without notice. Fix: Use the same pitch limits in both places and keep the game camera's actual pitch when it is inside the range.
- **low** `:118` — The wheel zooms toward the orbit target, not the cursor, and has a hard 0.5 m minimum, so working on small items or zooming to a point of interest is awkward and the limit is silent. Fix: Zoom toward the point under the pointer (move the target as well), and let the minimum distance scale with the target's size.

## crates/editor/src/data_panel.rs

- **medium** `:1` — Every change of a data asset is written to disk at once with no undo, no 'Saved' feedback, and no hint in the UI; a slider drag overwrites the file every frame and a mis-click cannot be reverted. Fix: Show a small 'Saved/unsaved' state in the header and hook the edit into the editor undo stack (or at least keep one 'Revert to last opened' button).
- **medium** `:70` — The name error lists letters, numbers, `_` and `-` but the code also accepts spaces, and says nothing about which character is wrong; the 'is there already' error gives no next step. Fix: Say 'Use letters, numbers, spaces, `_` or `-`; `<char>` is not allowed.' and 'data/<name> exists; pick another name or open it from Open data asset.'
- **medium** `:89` — `open_data` replaces the open data asset (and, on a failed open, leaves the old one showing) with no sign of what happened except an error that is not tied to the file the user clicked. Fix: Set a status line 'Opened <file>' on success, and on failure prefix the error with the file and say what to do ('fix or delete the file, then open it again').
- **medium** `:157` — After an error in 'New data asset' the menu is closed anyway, so the user must reopen it to retry and the error appears away from the menu. Fix: Close the menu only on success; on error keep it open and show the message in red under the name field.
- **medium** `:179` — The header shows only the file name and a bare 'Close' button: two assets with the same name in different folders look the same, the type is not shown, and Escape does not close the panel. Fix: Show the type and the project-relative path (full path as hover text), label the button 'Close data asset', and close on Escape when the panel has focus.
- **low** `:118` — 'Open data asset' lists raw relative paths including the data/ prefix, unsorted by type, and unknown-type files are only explained on hover of a disabled button. Fix: Group the files by type with the folder prefix stripped, and show the 'No module registered this type' reason as a weak suffix on the row.
- **low** `:133` — The type pick is a bare button showing the current type name, with no label and no hint that it is a dropdown; the name field's hint 'name of the data asset' is cut once text is typed and the type/name pair is not visibly a form. Fix: Add labels 'Type' and 'Name' (or a down-arrow on the type button with a hover text) and put the file result 'data/<name>.<type>.ron' as a live preview under the fields.
- **low** `:186` — In play mode the data fields are silently greyed out with no reason given, and the 'Assets' entries are disabled the same way. Fix: Add a weak line 'Stop play mode to edit data assets' (and the same as hover text on the disabled menu items).

## crates/editor/src/event_panel.rs

- **medium** `:404` — A picker with an empty value renders as a blank, nearly invisible combo, and a picker whose list is empty (no lights, no doors, no spawn points, no outputs) opens a popup with only a search field; the user gets no hint to add such an object. Fix: Show a placeholder like '(none)' in red for an empty value, and put a weak line in the popup such as 'No lights in this room. Add one from the Add menu.'
- **medium** `:443` — A new text key is written to the text table on disk at once, before the user saves the room or can undo, and its text is empty with no warning or field to type the text. Fix: Add a text edit under the key pick for the text of the key (or a link to the Texts dock) and warn while the text is empty.
- **medium** `:654` — New Choice, new Answer and new Message commands use placeholder keys ("Question?", "Answer", empty) that do not exist in the text table, so the pick shows red right after Add. Fix: Create keys in the table on Add, or start with the key pick open on New... so the user types the key.
- **medium** `:1119` — Deleting a page, deleting a wire (1227), removing an answer (640) and removing a condition drop their commands with no confirmation and no notice. Fix: Ask for confirmation when the page, wire or answer has commands, or show a toast with an Undo action.
- **medium** `:1208` — Add a wire on an object with no outputs creates a wire with an empty output and an empty picker, with no message that the object has no outputs. Fix: Disable Add a wire with a tooltip 'This object has no outputs' when own_outputs is empty.
- **medium** `:1270` — Add puts the new command inside the first branch of a selected If/Choice (insert_place), while Paste and Duplicate put it after the selected rows, so the same selection gives different places. Fix: Use one rule for all three (after the selected row; inside a branch only when a branch row is selected) and show an insertion line where the command will go.
- **medium** `:1326` — Drag and drop can only drop a command before another row, so a command cannot be moved to the end of a page or of a branch, and there is no keyboard way to move rows up and down. Fix: Add a drop zone after the last row of each list, and Alt+Up/Alt+Down (or Move up/down buttons) for the selected rows.
- **low** `:384` — The new-name field cancels without notice when the user clicks elsewhere, so the typed name is lost, and an Enter on an already existing name is ignored. Fix: Keep the field until Enter or Escape, and on an existing name just select that name.
- **low** `:1086` — Page tabs are bare numbers with a star, the star meaning is only in a tooltip repeated on every tab, and the tab of a page with no conditions or trigger cannot be told apart. Fix: Show the trigger and condition count in the tab tooltip (e.g. '2: Touch, 1 condition') and explain the star once in a legend next to the tabs.
- **low** `:1104` — The page buttons Add, Duplicate, Delete, <, > do not say that they act on pages and sit near the command buttons Delete, Duplicate, Copy; the arrows are cryptic, and Add and Test this page vanish when a wire is selected. Fix: Label them 'Add page', 'Duplicate page', 'Delete page', 'Move earlier/later', and keep page buttons visible (disabled with a tooltip) while a wire is shown.
- **low** `:1280` — The Add command list is a plain combo with all command names in registry order and the label 'Add' on the button, so it reads like a page button and has no groups or recent commands. Fix: Label it 'Add command...' and group the names by module (flow, flags, light, sound) with the help text visible in the entry.
- **low** `:1310` — Delete, Duplicate, Copy and Paste of command rows give no feedback (Copy shows nothing, Paste does not say how many commands), and the shortcut shows only in a hover text. Fix: Show the key in the button label or tooltip next to a short action name, and display 'Copied 3 commands' / 'Pasted 3 commands' in the status line.

## crates/editor/src/gizmo.rs

- **medium** `:324` — A light's Aim handle always sets the direction to a floor point, so a spot light can never be aimed upward or sideways, and the handle jumps to the floor after the first drag. Fix: Hold the drag plane at the handle's current height (or use Alt/Shift to aim in 3D) so the direction is not forced onto y=0.
- **medium** `:381` — Each doorway corner drag also rewrites the doorway height from the pointer's height, so dragging sideways to change width unintentionally changes the height, and there is no way to change only one. Fix: Change width/offset with the horizontal pointer movement only, and add separate top-edge handles (or a modifier key) for height.
- **medium** `:432` — The rotation snap is applied to the drag delta, not the resulting angle, so an object at 17 degrees with a 15 degree step stays off the grid (17, 32, 47). Fix: Snap the final absolute angle of the item (when a single item is selected) or document that the snap is relative.
- **medium** `:461` — Scale has only per-axis handles; there is no uniform scale (center handle or Shift-drag), and dragging an axis through the origin silently pins the scale at 0.01. Fix: Add a center square for uniform scale and show the clamp (or mirror) instead of silently pinning to 0.01.
- **low** `:147` — The Scale tool ignores the Local/Global toggle (always local axes) without telling the user, so the toggle seems broken when Scale is active. Fix: Disable or grey out the Local/Global control with a tooltip 'Scale is always local' while the Scale tool is active.
- **low** `:191` — Pick order and reach make rings and handles hard to grab: in the default top-down view the X and Z rings are edge-on lines, and the 9 px reach on thin handles is small with no hover highlight exposed by the gizmo. Fix: Expose the hovered Handle from handle_at for highlighting, and raise REACH or use a pixel-distance tie-break that prefers the axis facing the camera.
- **low** `:329` — When the pointer ray does not hit the floor (pointing above the horizon) the aim, area-corner and rotate drags silently do nothing and the object freezes with no feedback. Fix: Keep the last valid result and show a hint, or project onto a plane at the horizon so the drag continues.

## crates/editor/src/lib.rs

- **medium** `:639` — Add, MakePrefab and UnpackPrefab failures (lines 639, 716, 730) put the reason only into the status row, not a notice, so a failed 'Make prefab' looks like nothing happened. Fix: Route these reasons through self.fail-style notices (warning level) so they appear as a toast.

- **medium** `:1588` — A Test of an event whose object was deleted or whose room never loads retries start_event forever with step mode on: the game starts frozen with no message. Fix: Give up after a few frames or when the object is gone, set step mode off, and notify 'The event could not be started'.
- **low** `:531` — Row commands set the status from the Debug text of the enum ('Delete: command rows', 'Paste: command rows'), even when nothing changed, e.g. paste with an empty buffer. Fix: Use friendly messages with counts ('3 command rows deleted') and say when nothing was done.
- **low** `:575` — New room followed by Save writes untitled.ron into the room folder with no name prompt, so rooms are easily overwritten or left with a meaningless name; status only says 'Saved'. Fix: When the document file does not exist yet, make Save open the Save as name dialog, or include the file name in the 'Saved' status.
- **low** `:586` — A failed Open sets the generic status 'The command failed'; the real reason is only in the notice, and nothing says the old room is still open. Fix: Use 'Could not open <file>: the current room is unchanged' as the status.
- **low** `:645` — Delete and Cut report 'Deleted' with no count and no hint that Ctrl+Z restores; Add says only 'Added' without naming the kind. Fix: Status such as 'Deleted 3 items (Ctrl+Z to undo)' and 'Added Light'.
- **low** `:666` — Undo status '3 steps back, 1 forward' is ambiguous: it does not say what was undone. Fix: Name the step ('Undid: move Crate') or at least '3 more steps to undo, 1 to redo'.
- **low** `:672` — Copy/Cut/Paste statuses read '1 items copied', '1 items pasted'; Copy/Cut with an empty selection replaces the buffer with nothing and says '0 items copied'. Fix: Pluralise properly and, for an empty selection, keep the old buffer and report 'Nothing selected'.
- **low** `:738` — Frame uses a fixed distance of 4.0 for every item, so a large mesh or a whole wall is cropped and a small prop is far away; Frame also gives no feedback when the item has no pose and the whole room is framed. Fix: Derive the distance from the item's bounds (fall back to FRAME_DISTANCE) and set a status when it frames the room.
- **low** `:820` — Renaming an item to an empty string silently removes its name, which can break events and commands that refer to it by name, with no warning. Fix: Reject the empty name (keep the old one with a status line) or warn when other events use the name.
- **low** `:862` — Playing a room with no spawn point silently starts the player at the camera target; the user is not told why the player appears at a random place. Fix: Set the status to 'No spawn point: playing from the view centre' (or warn before play).
- **low** `:1051` — Quit is disabled while playing (can_run = editing) and the window close button only stops the game, so closing a playing editor takes two clicks with no hint. Fix: Show 'Stopped. Close again to quit' in the status when the close request stopped a game.

- **high** `:353` — Add > Button silently wires `OpenDoor(0)` when the room has no door or mover, so the button looks done but does nothing and no message says so. - **medium** `:272` — Add > Door always picks the first doorway with no door, not the selected doorway, and the error "Each doorway has a door: add a doorway first" is wrong/confusing when the room has no doorway at all. - **low** `:666` — Older undo steps are dropped silently at 200, and `undo`/`redo` only return a bool, so the UI has no way to say "Undid: Delete cube" or that history ran out. Fix: Store a short label per step and return it from undo/redo for the status line.
